# QQ 接入后端

开发中。本批将 NapCatQQ 与 SnowLuma 接到相同 OneBot v11 边界。配置解析、带版本核对的选择接口、按后端替换的页面和安全启动控制已实现隔离验证；真实安装登录、运行部署及完整业务验收仍待完成。当前说明不表示在线实例已经切换。

## 边界

DSH 继续运行同一个角色、记忆和决策系统。QQ 后端仅负责平台连接，不替换主 LLM，不另起判断模型。安装脚本所在的 `napcat/` 是已有服务目录，目录名不决定所选后端。

`scripts/qq_backend.py` 定义后端描述、配置解析、私有连接、公开连接摘要及 OneBot 调用。控制台、Python 和 PowerShell 消费者共用该边界。PowerShell 通过隐藏子进程的私有管道读取连接，不将令牌放进参数或日志；每次配置装载读取一次，不按消息分片重复启动解析进程。

## 配置

```json
{
  "qqBackend": {
    "provider": "napcat",
    "providers": {
      "snowluma": {
        "root": "snowluma",
        "httpServer": "http-default"
      }
    }
  }
}
```

`root` 相对于工作区，也可由本机配置明确指定安装目录。未配置 `qqBackend` 的安装保持 NapCatQQ。未知后端、选中后端的损坏配置或歧义 HTTP 监听器均拒绝连接，不用另一套令牌或另一个在线后端掩盖错误。

Python 与原生 JavaScript 都优先读取可信 `LANYA_PROJECT_CONFIG`；显式文件缺失或损坏时拒绝读取，不回落到其他配置。显式配置文件的相对路径以进程当前目录为准，支持用户目录展开；后端 root 则相对于运营工作区。原生适配器可通过可信 `backendWorkspace` 或 `LANYA_WORKDIR` 指定运营工作区，与角色对话目录分开。

NapCatQQ 读取其 `config/onebot11.json` 中的 `network`。SnowLuma 读取 `config/onebot.json` 与可信账号对应的 `config/onebot_<account>.json`；账号来自显式本机配置或当前角色的 `botQQ`，不枚举猜测其他账号。账号快照排除全局配置，覆盖按完整的同名适配器替换，避免继承另一适配器的令牌。HTTP 与 WebSocket 令牌可以不同。

多个启用的 HTTP 适配器需通过 `httpServer` 明确选择。现有 NapCatQQ 采用 `onebotPort`。端点由本机配置确定，当前连接器只接受回环地址，保留路径前缀；不会跟随携带授权头的重定向。HTTP 200 之外还需检查 `status` 与整数 `retcode`，失败不能展示为空联系人列表或成功投递。

公开摘要仅含配置事实，不证明进程已加载、WebSocket 已连接或 QQ 已实收。令牌不返回其前缀或后缀；反向连接 URL 中的查询参数也不回显。

## 部署与切换

首次部署可用 `install.ps1 -Target <workspace> -QQBackend snowluma` 或 `-QQBackend napcat` 选择后端；`-WhatIf` 不写文件。安装器只部署本库代码，不下载或安装供应商程序。已有项目的选择继续受到配置保护：更新代码时省略该参数，在已加载切换保护后通过部件页切换，避免安装复制过程中改变在线账号。

部件页提交所读配置的精确 revision，保留完整原件及权限后替换配置，并递增接入代次。配置改动、目标改动、未加载保护或兼容工作进程尚未退出时拒绝在线切换。选择本身不停止、启动或登录 QQ；已安装但尚未生成 OneBot 配置的后端可进入首次设置。

主 Agent 对实际 WebSocket 做一次后端版本与账号核验，结果只在同一个 socket 和选择代次内复用；收件、模型准备和最终传输仍核对代次。不会给每条消息增加 Python 解析进程或重复握手。选择改变后，前一套连接不能继续代发。

版本或账号不符的连接持续拒绝收件，重新建立连接后再核验；短暂读取失败保留一秒冷却，避免消息密集时重复握手。Python 与 JavaScript 共用配置测试向量，显式空值、歧义监听、账号覆盖及路径边界使用相同规则。SnowLuma 的 HTTP 适配器属于具体账号实例，不通过任意请求头选账号；多账号应在供应商中配置独立监听，并核对实际 `get_login_info`。

历史锚点也属于后端能力：NapCat 的有界引用查询使用 `message_seq`，SnowLuma v2.4.1 使用整数 `message_id`，保留负数消息编号。增量编译器 `patch_onebot_backend_context.py` 将既有桥与引用解析层接到同一个后端描述，必须和主适配器成对部署。原有范围、作者、三张引用图片和总超时核验不变，不能因参数不兼容改成跨会话扫描历史。

`patch_onebot_backend_transport.py` 只接受已审 OneBot 0.8.1 连接模块的精确 SHA，生成独立候选，不自动安装。正向与反向 WebSocket 的消息回调都核对实际连接身份；替换反向连接时，原先等待的调用立即以“结果未确认”结束，不等完整超时，也不在新连接重发。原请求可能已到达平台，不能把本地等待结束当成平台未发送。

切换保护同时核对实际加载的连接层和引用层版本 getter、桥的历史能力函数及新鲜心跳；磁盘复制完成不能证明运行进程已更新。受控部署须包含连接模块、桥、引用层、主适配器与预算心跳辅助程序，保留原件后重载同一个宿主，再读回两项运行就绪标志。旧心跳仍可记账，两项标志默认未就绪；人民币金额、额度和既有账本口径不变。

接入页按所选后端显示管理页、启动检查、连接核验及共用资料、好友和群列表。配置选择和账号在线分别显示；旧地址转向当前接入页。后台组件状态只采用新鲜且匹配当前配置的核验记录，端口可达不等于账号在线。页面并发读取共享同一结果，切换前的异步回包不能覆盖当前页面。

配置元数据读取失败时，健康检查、资料保存和联系人刷新均显示明确的终止状态，恢复后可重新读取；不保留“检查中”或静默忽略操作。后端脚本资源不可用时只停用接入操作，不阻断 B站、花销或记忆等其他页面。

看护只检查所选后端，不按进程名称强杀 QQ，也不周期触发提权。SnowLuma 的已有运行程序需要确认登录时保留其 WebUI，不再重复启动；未知启动意图或进程身份需要先核查。NapCat 连接异常时报告需要检查，不把断连当成可以关闭整个 QQ 客户端的依据。

两种启动器共用项目锁与 `napcat/backend-runtime/` 持久记录，位于角色可写目录之外。先保存启动意图，再核验实际 PID、创建时间和可执行文件；确认创建不代表已登录。接口超时或无法核验的结果不自动重试。已完成记录保留最近一批，其余逐项核验后移入同目录归档；恢复原件不删除。另一个后端的进程、HTTP 或管理页仍在运行，以及配置损坏导致无法确认时，均不启动第二套接入。

NapCat 启动器按所选 `root` 核对注入文件，启动脚本可在本机的 `qqBackend.providers.napcat.startScript` 指定，相对路径以该后端根目录为准。兼容已有 `napcat.startScript` 和 `LANYA_NAPCAT_LAUNCHER`；后台窗口隐藏。调用可能关闭 QQ 的本机脚本前，必须确认没有正在运行的 QQ 客户端；无法确认时保留现状并提示人工核查。

修改昵称、签名或头像前，单独核验所选后端和角色 `botQQ`。资料缓存按后端及账号隔离，不显示未经归属核验的历史签名或头像；本机原文件继续保留。每个实际修改前仍检查配置指纹。读取资料、接口接受修改、缓存保存和手机显示是不同证据，部分修改失败会分别报告。

## 外部软件

SnowLuma 独立安装并保留自己的 WebUI、登录、协议确认及账号数据。本库不包含其二进制、专有组件或上游源码，不绕过其认证、首次协议或改密步骤。实际安装与操作需遵守发行包自己的要求。
