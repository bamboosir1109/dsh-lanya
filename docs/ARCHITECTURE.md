# 系统架构

## 三份内容的职责

| 位置 | 职责 | 更新方式 |
|---|---|---|
| Git 仓库 `dsh-lanya/` | 公开源码、默认配置和使用说明 | 代码审查、测试后提交 |
| 工作区 `napcat/` 与角色 `made/` | 后台程序、面板与运行日志 | 安装器部署，按进程重启 |
| DSH profile 中的插件 | 宿主加载的 JS 与 bundle patch | DSH 插件管理或源码 link，再重启 |

角色身份、日记、人物档案、记忆和账号凭证属于本机运行数据。它们不会因为源码仓库更新就搬进仓库，也不应在公开问题报告中原样附上。

## 消息和自主活动

```text
QQ 消息
  → NapCat
     或 SnowLuma（私聊、群聊、引用图、表情和语音已实机验收）
  → OneBot / dsh-onebot-qq
  → DSH agent：角色提示词 + 身份 + 记忆 + 工具
  → qq_decide：回复 / 安静 / 内部工具 / 持久控制
  → 带固定许可的最终 QQ 出口

groupwatch / mind / greet / reminders / B站 → 持久观察队列 → 同一聊天 agent
控制台        → Python API → 本机文件、外部服务或后台脚本
```

一个 DSH 宿主内，每个私聊用户和每个群各有独立的 ChatAgent、session 与持久 inbox；同一会话按轮次处理，不同会话的模型与工具等待可以并行。这里的“同一主 LLM”是统一决策方法和角色，不是让全部 QQ 会话共用一个全局模型队列。宿主的辅助进程也不能直接算作重复聊天实例。

QQ 后端通过独立配置、连接解析和生命周期接口扩展，不在聊天策略中按端口猜测。配置选择、实际加载、版本与账号核验及客户端收件分别记录。原生桥把核验结果绑定到真实 socket 和选择代次，最终传输再次检查；切换不复制会话或更换角色。详见 [QQ 接入边界](QQ-BACKENDS.md)。

连接层在解析前拒收已被替换 socket 的迟到帧，反向替换立即结束原调用等待而不重试未知发送。实际加载的传输和引用能力随预算心跳投影；磁盘文件哈希与这两项新鲜运行标志一起决定能否在线切换。旧心跳继续兼容记账，但不能证明新能力已加载。

自主观察由唯一消费者读取，按会话顺序派发，并限制同时执行的会话数量；一个慢会话不能占住整个观察扫描。新的轮询仍可发现其它会话的后到事件，同一会话不重复派发。在飞轮次结束前，停机不会提前交出消费者租约。个人自主活动目前沿管理员私聊会话处理，群内机会沿各群处理；没有为了并行而新建临时会话、搬走历史或复制个人娱乐。

任一原生轮次已有结果不明或部分发送时，本轮后续 QQ 输出停止，包括换一段文字、换图或把内部处理说明当作最终答复；只读内部工作仍可继续。已确认成功的消息保留，结果不明的原件不补发；新的真实输入形成独立轮次，不继承上一轮的停发标记。

`groupwatch.ps1` 是长驻群监听，使用独占 `groupwatch.lock` 防止重复实例。锁文件存在或时间戳较旧，不等于进程失效；是否能持有独占句柄才是判断条件。

`mind.py` 按次执行并保存观察时钟。unified 模式只在新证据或主模型指定的复查时刻写观察，无新证据不会每分钟调用模型。两轮之间没有 Mind 进程是正常状态。旧 life/agentchat/voice 直接发送入口暂停并保留积压；legacy 模式才保留原独立决策。实现与切换约束见 [主 LLM 决策](DECISIONS.md)。

同一主 LLM 用 `qq_intent` 保存所属会话的目标、简短理由、下一步与状态，后续上下文继续读取。意图存储按工作区、角色和会话隔离，以修订号防止并发覆盖；计划和自述进展不等于真实完成。工具回执元数据单独保存，不存隐藏推理。自主活动页只读展示管理员与配置群的当前计划，实际动作仍以工具记录核对。

主动联系先读取有真实关系证据的候选，再请求目标自己的社交机会；接收会话由同一主 LLM 读取自己的上下文、重新决定并取得自己的发送许可。主会话的票和聊天原文不能跨会话使用。群内非好友只尝试明确的单用户私聊路线，平台是否接受取决于 QQ；不能因私聊失败改发到群。当前 NapCat 注册能力没有关键词搜群或主动申请入群，不能将处理已收到的申请接口冒充此能力。

活动读取器按已核验原生轮次归并工具事实，保留触发来源、结果状态和证据；自主观察、真实 QQ 入站与无法归因的记录分别标明。工具返回、选图、平台接受与实际送达不能互相替代。活动页只显示近期经过，等待和决策单独折叠。

`activity_journal.py` 复用同一事实投影，按北京时间完整日期生成本机每日回顾。既有 Mind 的自然周期更新当天并逐次追补当前可信源中的未归日日期，无新模型和独立调度器；专用目录与清单保护现有日记，更新失败不阻塞自主机会。日记不含聊天原文、隐藏推理或原始命令，不进入 QQ 群上下文。当前覆盖限已配置管理员与群的当前映射会话，日终快照也不表示全账号或源历史完整。

后台定时作业可能由 DSH 内置调度或独立 supervisor 驱动。两者通过标记与健康状态避让；排查时要确认当前实际负责调度的一方和日志更新时间，不能仅凭任务存在认定任务正常。

### 调度模式

| 插件设置 | 默认值 | 作用 |
|---|---|---|
| `schedulerEnabled` | true | false 时关闭插件周期作业、提醒与面板看护，由外部 supervisor 接手 |
| `scheduleBili` | false | true 时插件额外调度视频每 10800 秒、社交每 5400 秒；避免和其他 B 站 bundle 同时负责同一作业 |
| `pythonExecutable` | PATH 中的 `python` | 插件启动 Python 作业使用的程序 |
| `dshExecutable` | PATH 中的 `dsh` | 插件调用 DSH CLI 使用的程序 |

内置调度每 15 秒更新 v2 JSON 标记，记录宿主 PID 和负责的 jobs。外部 supervisor 只避让标记在 120 秒内更新、PID 仍存活且明确列出的作业；单独残留一个老 flag 不再让所有后台工作永久停止。这不是跨机器的分布式锁，仍应明确选择一方负责调度。

`ensure-tasks.ps1 -Scheduler External` 默认补外部 supervisor；若已经存在本工作区启用的独立 Budget 任务，supervisor 避让该兼容作业。`-Scheduler Plugin` 不新增 supervisor 或独立 Mind 任务，保留独立 Budget 任务的兼容安排。旧预算脚本不是统一主 agent 的费用门控；新版在可信 turn 入口与动作入口核对，见[统一预算与设置](DECISIONS.md#统一预算与设置)。

任务注册只补缺失项，不改删已有定义。旧独立 Mind 或另一调度器任务如果还存在，需单独核对，不能把新模式当成自动迁移器。`start-all.ps1` 同样接受 `-Scheduler External|Plugin`，但不会修改 DSH 插件配置或关闭已启动的另一方。

### 提醒投递

unified 模式由插件把到期提醒提交给主 agent，PS 直接发送入口暂停。`pending/decided/suppressed/unknown` 都不记已送达；只有原观察的 `sent` 完成证据才消费一次性提醒。普通安静不反复唤醒；结果不明不自动重试。显式 legacy 回退仍共享 `reminders.state.json`、稳定内容键与跨进程锁。并发编辑清单时不覆盖新加入的条目。

`daily` 提醒默认允许在当天到期后 5 分钟内补发，可在条目中用 `dailyGraceMinutes` 设置 0–60；0 表示只匹配到期分钟。超出窗口不补发，避免重启后集中追发历史提醒。一次性 `at` 提醒按到期时间判断，不使用这个 daily 窗口。

## 控制台读取层

| 模块 | 职责 | 边界 |
|---|---|---|
| `panel_activity.py` | 捕获稳定来源、逐行解压、归并工具与原生轮次事实 | B站、活动及每日事实共用；校验所有权与种子边界 |
| `panel_read_cache.py` | 对已核验的工具元数据作进程内短缓存 | 当前读权限和文件身份每次核对；不缓存原始对话、错误或许可 |
| `budget_runtime.py` | 当前额度、预留和执行账本 | 摘要不触发原生历史扫描，报表不改此账本 |
| `budget_reports.py` 与 `budget-native-report.mjs` | 有界提取用量并调用原生计价投影 | 人民币数值原样；不完整计价与对账保留未知 |
| `panel_health.py` | 逐页检查实际嵌套数据与加载耗时 | 只读本机，不发 QQ／B站请求，不输出正文和账号 |

`/api/budget/summary` 只提供执行门控信息；`/api/budget` 包含完整每日统计。活动页复用响应中的预算摘要，不再额外加载日报。记忆概览、日记和文件列表独立并行，不让其中一项延迟阻塞其它项。

工具事实缓存只保留 JSON 元数据，最多四个来源、每项 8 MiB、五秒有效；不同归属、文件替换、追加、当前读权限丢失等重新核验。单个缓存只有一个构建者，等待最多十秒，错误和超大结果不缓存。两个端口是不同进程，各有独立缓存；它不替代 SDK 或发送侧检查。

后续原生轮次的递增编号可以证明前轮被中断，不能证明前轮已完成。工具原始回执保留，无法确认的触发归因与费用保持未知；同号／倒序或错误的结束配对仍拒绝。原生计价和活动投影都遵循这个边界，避免一次重载使之后所有记录失效。

## 工作区布局

```text
<WORKDIR>/
  dsh-lanya/                    源码仓库
  config/project.json           新安装的本机项目配置
  napcat/
    lanya-panel-server.py        面板后端
    project_conf.py/.ps1         配置与目录解析
    mind.py、groupwatch.ps1…     后台脚本
    persona.md                  新安装的人设
    framework/                  另行安装的 NapCat
    config/project.json         兼容旧安装的配置位置
  <dataDirName>/
    lanya-config.json           身份与消息目标
    lanya-tunables.json         群聊节奏
    autonomy-budget.json        CNY 限额、每轮预留与明确记账依据
    autonomy-budget.sqlite      可信轮次费用与预留账本
    autonomy-intents.sqlite3    按工作区、角色、会话隔离的目标与下一步
    people/、diary/、notes/      人物档案、日记、随笔
    activity-journal/            按可信归属隔离的每日事实回顾
    chats/、memes/               聊天导出、表情素材
    made/
      lanya-panel.html          控制台入口
      theme-light.css           样式
      phone.html                手机页
```

本地长期记忆数据库与 B 站凭证通常还位于 DSH 用户目录。具体文件由相应插件及读取器决定；复制角色目录不能替代完整备份所有依赖的数据。

## 默认端口

| 端口 | 服务 | 说明 |
|---|---|---|
| 19387 | DSH GUI | 宿主独立管理 |
| 19388 | 控制台与作品页面 | `lanya-panel-server.py --port 19388` |
| 19389 | 面板 API | 同一脚本的另一个实例 |
| 8720 | NapCat OneBot HTTP | 外部协议桥 |
| 6099 | NapCat WebUI | 外部管理页面 |
| 9880 | 本地 TTS | 另行安装的 GPT-SoVITS |

面板只读请求优先使用同源 API，默认 19389 是备用；写操作仍使用默认 API 端口。部分辅助脚本也保留默认端口或旧路径。调整项目端口后，要核对对应调用方，不能只改一处 JSON 就假设所有页面都已跟随。面板服务仅应在可信本机环境使用，当前不是面向公网的多用户服务。

## 配置读取规则

Python 使用 `scripts/project_conf.py` 的 `get()`、`work_dir()`、`data_dir()`；PowerShell 对应 `Get-ProjectConfValue`、`Get-ProjectWorkDir`、`Get-ProjectDataDir`。安装后这些读取器与脚本一起位于 `napcat/`。

明确设置的 `LANYA_PROJECT_CONFIG` 优先。源码中的 `scripts/`、`server/` 使用仓库自己的 `config/project.json`，避免测试自动读到相邻线上配置。安装到 `napcat/` 后，兼容查找顺序为 `napcat/config/project.json`、工作区 `config/project.json`。显式配置缺失、优先候选坏 JSON、非对象或不可读时停止；不会转选其他 legacy 配置重新开放发送。完全没有配置候选时才用默认 unified。重新读取失败也不保留旧的开放缓存；安装器同样拒绝覆盖已有坏配置。

`LANYA_WORKDIR` 可明确指定工作区。数据目录由选定项目配置的 `dataDirName` 决定；不会再因旁边某个旧目录文件较多就覆盖明确配置。源码运行时若要连测试布局，显式传入测试配置和工作区，避免依赖命令行当前目录。

JS 插件可在自身配置中设置 `workDir` / `workspacePath`，并读取环境变量及项目配置。插件使用实际安装包时，其当前目录不一定等于工作区，因此安装说明要求显式设置工作区。

## 配置与状态的区别

`config/project.json` 管端口、目录、超时和 `mind.opportunityMin`；`lanya-config.json` 管身份和消息目标。旧 `lanya-tunables.json` 仅供群观察器启动配置兼容，页面不会将它宣称为当前进程已加载值。`autonomy-budget.json` 保存新版限额，SQLite 保存实际轮次费用与未决预留；计划、锁、调度标记和日志各有对应写入者。

费用按模型原生轮次的估算数值记录，由所有者确认直接采用人民币口径，`currency=CNY`、`basis=owner_confirmed_numeric_cny_estimate`，不作汇率换算。来源仍明确保留成本插件默认报价估算的属性，不称服务商实扣。分类按可信触发来源区分自主、私聊和群聊，不从会话名字猜分类。轮次开始前预留，动作执行前再检查；结果不明保留预留，不自动退款或重试。账本只覆盖启用后的真实记录，不把未覆盖统计补成零费用，也不是服务商账户硬限额。历史 `budget.json` / `activities.json` 可以保留，不决定统一主 agent 的额度或活动权限。

零花钱的每日统计由 `budget_reports.py` 与 `budget-native-report.mjs` 只读重建当前可信映射的原生轮次，复用已安装成本插件的原始计价函数，再按本项目明确的数值记账依据输出 `daily-spending/v2`。原数值直接以 CNY 展示，保留来源单位与估算依据，不修改全账号成本插件账本。分类取轮次的真实触发来源：自主观察归自主，真实 QQ 入站按已核验范围归私聊或群聊；同一聊天会话中的自主活动不会再算作实时私聊。按北京时间归日，提供每日三类柱状图与明细；覆盖不足或缺失计价保留未知。该报表独立于预算执行账本，既不回填门控，也不将两者相加；不是服务商发票或全账号成本。
