# 统一决策与运行改进开发目标

状态：实施与分项验收进行中。更新日期：2026-10-30。

本目标覆盖角色系统的决策、QQ 会话、记忆、安卓操作和部署整理。本文保留目标设计；已实现协议以 [DECISIONS](DECISIONS.md)、[MEMORY](MEMORY.md) 和对应源码为准，设计字段不等同于现有存储字段。源码实现、安装副本、宿主加载与实际验收分别记录，安装与维护方式见 [安装](INSTALL.md)、[架构](ARCHITECTURE.md) 与 [维护](MAINTENANCE.md)。

用户当前优先顺序：先完成 G00 的恢复点和 G08 的工作区整理，再做业务二次开发。清理保留活动路径与原始数据，不靠删除或未经验证的路径迁移换取整齐。

当前实施边界：已提供可逆归档、统一决策与观察队列、范围记忆及原生事实历史、无损压缩胶囊、真实 Android 截图协议与离线 replay 隔离。普通与后台 turn 共享[可信能力说明](CAPABILITIES.md)，[语音](VOICE.md)和 B 站动作仍由同一 agent 按真实工具结果判断。离线 fixture、实际安装源码的隔离验证和用户现场反馈各自说明覆盖范围；不把一次静默反馈或一次部署核验推广为所有场景通过。Android 开机、真实截图与连续动作仍需具备固件虚拟化条件的设备验收。记忆接口与兼容边界见 [MEMORY](MEMORY.md)。

原生memento事实写入已另接同事务全行历史与整批恢复fixture，审批等待期间目标变化会拒绝。部署需先可见性补丁、后原生历史补丁；历史从启用后保留，不能补回过去已丢失的完整行。

## 目标行为

角色由一个主 LLM 决定是否回复、是否继续娱乐、是否操作工具以及何时再次观察。判断依据包括人设与行为 prompt、当前聊天上下文、短期状态、相关长期记忆、当前计划和真实工具结果。

“一个主 LLM”指同一套决策入口、上下文规则与状态所有权，不要求所有工具都挤进同一进程。浏览器、安卓、语音和网络模块执行动作、返回事实，不各自随机决定要不要找人聊天。

沿用已有 DSH 模型与会话入口作为第一版实现，不预设新增模型供应商或 API 凭证。模型能力、视觉输入和实际可用工具在集成时验证；文本内容、网页玩具和缓存图不能冒充真实手机观察。

触发事件只表示“可以判断”，不意味着必须发消息。@、私聊、冷场、定时器和任务完成都允许安静结束或延期。现行 `qq_decide` 使用 `idle/defer` 表示本轮不发言，`silence` 表示持久静默；不接受名为 `silent` 的 verdict。不得因为模型选择沉默、输出不完整或超时，再强求开口或补随机台词。

## 不变约束

明确的静默意图必须进入持久状态。模型理解自然语言的范围、时长和恢复条件；执行器在最终发送前验证该状态。静默后不能补发已排队的文字、图、语音、转发和后续气泡，也不能发“收到，我不说了”之类确认占位。

控制状态绑定稳定的聊天范围及发言人身份，不随新建模型会话或重启丢失。引用、转发、网页、他人的档案和跨聊天摘要属于参考内容，不能冒充当前用户的控制指令。

LLM 决定正常行为；程序负责事件去重、工具参数验证、预算、并发、静默约束及异常限流。限流只阻止异常，不产生“到时间了所以必须说一句”的行为。

原始记忆、身份、人设、凭证与活动中的运行目录不随整理删除。压缩生成摘要和归档，不以直接吞掉原文作为默认策略。

## G01 与 G02 会话和发送

### 事件进入

QQ WebSocket、群轮询、私聊、定时观察、提醒、工具结果和用户控制统一进入事件队列。事件至少包含来源、机器人身份、稳定聊天 scope、消息 ID、发言人、时间及证据引用。

同一个 QQ 消息即使由 WebSocket 与轮询重复收到，也只能有一个有效处理所有者。事件在失败后可重试，完成后可重放核对；不能因为模型失败提前消费掉未读事件。

短时间连续输入合并成一次上下文观察。没有新消息、没有到期任务且状态不变时，不重复唤醒模型。静默与取消事件优先于尚未发送的普通回复。

### 决策协议

完整决策记录的设计字段如下；当前主模型只调用qq_decide提交候选verdict/control_update/next_review_at，scope、actor和revision由可信适配器绑定，不能作为模型权限参数。具体已实现协议以[DECISIONS](DECISIONS.md)为准，其余设计字段不冒充已经存储或上线：

| 字段 | 用途 |
| --- | --- |
| decision_id、event_id | 决策与事件关联，支持幂等 |
| scope、actor | 聊天范围与可信发言人身份 |
| context_version | prompt、人设、记忆与控制策略版本 |
| kind | 设计中的行为分类；现行工具使用 verdict=reply/idle/defer/silence/resume/tool_action |
| control_update | 静默范围、期限与恢复条件 |
| actions | 允许执行的消息或工具动作 |
| next_review_at | 下次需要观察的时间 |
| reason_code | 简短原因类别，用于排障，不保存思维链 |

决策和控制字段只供程序处理，不渲染成 QQ 正文。当前沿用同一聊天 agent 的判断与可选正文，不必为每条消息额外开一个分类模型。

没有明确时长的“先别说话”持久保持；恢复需要可信用户的明确恢复意图，或被语义判定为新的直接请求后按协议更新。不能把普通群聊、其他人 @ 或后台定时器当成自动解禁。

### 统一出口

发送 broker 覆盖被动回复、主动插话、自主分享、问候、提醒、图片、表情、语音、转发、重连队列与工具中的原始发送 API。

每个待发送项携带有效许可、聊天范围、来源决策、幂等键和 policy revision。最终网络调用前、重连补发前及分段发送之间都重新校验；静默会撤销旧许可。恢复后不倾倒旧队列。

当前 OneBot 的 guardedConnectionCall 已作为最终接入点，实际覆盖范围与边界见 [DECISIONS](DECISIONS.md)。原始 API、独立 HTTP 脚本和外部插件仍须逐入口核对；不能仅因 sendToChat、群 prompt 或某个发送分支通过，就把所有出口记为完成。

## G04 主 LLM 与功能执行器

主决策器维护当前意图、未完成动作、最近观察、会话控制和下一次检查时间。群监听改为观察器；mind 成为调度适配；B 站、语音、浏览器和安卓模块返回实际结果。

同一行为不能由群监听、宿主回复和自主循环各生成一次。模型上下文复用已有 DSH agent 能力，但长期状态与聊天范围不得只绑定临时 session ID。

娱乐和对话都可以选择继续、暂停、切换、等待或什么也不做。完成娱乐不强制向群里汇报。工具失败、设备离线和无新事实时，不能编造进展。

## G03 与 G05 记忆

| 层 | 内容 | 更新与保留 |
| --- | --- | --- |
| 短期工作记忆 | 最近聊天、当前计划、未读事件、工具结果与未决事项 | 有界窗口，跨轮次可恢复 |
| 长期语义记忆 | 稳定事实、偏好、关系、经历与明确承诺 | 主写入口，带来源和版本 |
| 原始证据 | 聊天事件、日记、人物档案、视频记录及截图 | 按范围归档，可追溯 |
| 派生压缩记忆 | 会话摘要、阶段摘要和主题整合 | 指向原文，随纠正重建 |

已修复可塑合并中保留项误删、不同事实被“留最新”替代、标题截短、压缩硬删与维护入口缺少归属约束等问题。机械层现在保留有界连续原文、逐行元数据与可恢复来源；共享空键的含义、查询范围及兼容边界见 [MEMORY](MEMORY.md)。事实库检索与会话原文历史属于不同入口，必须分别验证范围，不能用其中一项证明另一项。

主长期事实入口优先复用现有 memento 服务，统一 workspace、agent、读写策略、版本与审计。面板、种子、B 站和压缩不得各自无约束写同一数据库。已安装但未启用的其他记忆插件不能被当作第二个事实主库。

每条记忆记录 source_event_id、scope、人物标识、时间、版本、来源哈希及 derived_from/supersedes。引用频率影响召回权重，不把重复话术变成更可信的事实。用户纠正产生新版本，旧判断标为过时。

压缩先 dry-run，校验姓名、否定、日期、承诺、待办和来源覆盖，再事务提交。原文可归档但可恢复；SQLite 备份使用一致性 backup API，不单拷主 DB 文件而漏掉 WAL。

QQ 与 headless 的有效插件、工具权限和记忆可见性必须用无模型 fixture 验证。会话冻结快照和实时查询要分清：新事实不能因为旧快照存在就永久不可见。

## G06 与 G07 真安卓

先检查 CPU 虚拟化、系统加速、磁盘空间、现有模拟器和 ADB，再从厂商官方渠道安装一套可运行实例。项目接入设备发现、固定 serial、安装与启动状态、故障恢复和 screenshot/action 协议。

每轮遵守“取得当前截图 → 主 LLM 判断 → 一个动作 → 取得新截图”。动作与结果包含设备、seq、截图时间、尺寸和方向。过期截图、重复命令、断线或截图失败不能返回伪成功。所有 ADB 命令指定目标设备，不随意控制首个已连接设备。

验收包括打开 Android 系统应用、点按、滑动、返回、中文输入、旋转、截图更新、断线重连和多设备隔离。第一版用系统设置等中性应用验证，不借登录私人账号证明功能可用。

移除网页假手机、相关安装资产与 prompt 中的能力宣称，替换为真实设备画面和状态；设备不在线就显示不在线。现有网页浏览器功能仍可保留。旧网页及其可能的本地数据先可恢复归档，不再作为“手机可用”的回退。

## G08 清理归档

把源码、运行程序、角色数据、依赖、文档、实验产物与恢复材料分清。清理前检查进程命令行、计划任务、启动项、安装映射、插件配置和代码引用；不能按文件名或修改日期直接判冗余。

每批先生成 manifest，记录相对路径、大小、哈希、类别、归档理由、引用核对和恢复位置；应用后核对哈希及关键服务。首选可逆归档，同盘移动使用明确路径，不跨 shell 拼接删除命令，不跟随目录联接误移动外部文件。

Git 备份先核对提交、dirty 与未跟踪文件；浏览器 profile、模型、凭证、记忆、活动锁与当前日志不属于默认清理对象。归档本机数据不能进入公开仓库。

2026-10-30 本轮补充作品站与自主娱乐验收。2048 的 14 项规则/UI 测试及隔离浏览器离线交互已通过；其余完整回归、协调重载和真实主 agent 行为待对应收据，不以局部测试填为通过。3 分钟是本轮拟验证的机会配置，公开默认仍为 6 分钟，不是定时发言承诺。

| MEM-03 | 纠正、否定和同名不同人 | 事实、身份、时间与新旧版本可分辨 |
| MEM-04 | 压缩中崩溃、并发写与回滚 | 无原文丢失，归档与数据库一致 |
| MEM-05 | 视频记录归档后重新检索 | 仍能判重；旧日记按需可读 |

离线测试必须 mock 模型与外部传输。现有注入 dry-run 仍可能触发真实 agent，不能当成无模型测试。之后先影子比较，再用明确的现场用例验证实际行为；离线绿灯不冒充上线完成。

## 完成条件

全部工作包留下实现、测试、部署、回滚和文档记录。核心用例通过；真实 Android 操作有连续截图证据；归档可恢复；主 LLM 与记忆范围正确；线上切换后原有多入口不再绕过静默。未完成的硬件或人工步骤明确列出，不能提前把目标标为完成。
