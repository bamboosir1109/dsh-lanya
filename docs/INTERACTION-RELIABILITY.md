# 交互可靠性检查

功能注册、进程在线、模型写出回答、QQ 接受发送、手机显示消息是不同阶段。诊断不能把其中任意一步当作全部完成，也不因等待就重发结果未知的消息。

## 本批检查与修复

| 场景 | 处理与验证 |
|---|---|
| 同一私聊／群连续来信 | 原生会话队列条件允许时合并，不让按分钟的接收丢弃先吞掉最终追问；私聊、群各八十条隔离输入覆盖最终内容与预算预留 |
| 多人私聊、群同时来信 | 会话、待处理输入、角色和输出链按范围隔离；慢私聊准备期间，另一个私聊和群仍可分别入队 |
| 前半句话准备慢、后半句话先完成 | 较早已登记且 owner 明确的内容进入新输入的有界历史；只保留新输入的当前控制权限，早完成或晚完成均不能覆盖新绑定 |
| 已决定安静仍继续生成 | 接受 idle／defer／silence 后用当前 SDK 结轮接口结束，不为解释“不回复”再跑模型、触发下一步压缩 |
| 写了终稿却没有发送决定 | 实时聊天和仍有效的自主活动机会都可在同轮提醒一次，由主模型决定是否回复，原预算、会话和发送检查继续生效 |
| 群里被叫到后的连续接话 | 配置群旁听时由自主机会判断加入；真实艾特、核实引用回复或实际发言成功后才接普通后续消息，主 LLM 判断话题结束并回到旁听 |
| 引用、图片、语音和慢准备 | 原生管线回归覆盖实际对象、引用范围和图片格式；尚未完成解析不等于模型已读到媒体 |
| 新输入撤销旧回答、权限切换 | 维持 revision／owner／role 检查，不为提速允许过期输出或用旧管理员指令授权新成员 |
| 断线、负回执与未知发送 | 每个实际出口保留固定票、去重、预留和未知状态；未知操作不自动重放，发送链在失败后可处理未来独立轮次 |
| 预算、静默、夜间与取消 | 保留原生步前及工具／出口检查；真实来信与自主主动联系分别处理，不用取消来篡改未知费用 |

关键回归位于 `tests/test_onebot_live_inbox.mjs`、`test_decision_policy.mjs`、`test_onebot_egress_native.mjs`、`test_onebot_inbound_context.mjs`、`test_budget_gate.mjs`。其中 native inbox／driver 使用已固定的 SDK 方法片段，模型、传输和持久化边界按各测试说明使用隔离替身；这不构成平台或手机实收验收。

## 普通文字的单次决定

普通文字可用 `qq_decide({verdict:"reply",expression:"text",text:"完整回复"})` 在一次模型请求中完成决定与发送。执行层复用当前绑定和既有传输链，收到真实接受回执后结轮；同轮后续旁白和重复操作不再发出。旧的无text决定和媒体、多工具路径保持，不能把不回复或限定表达的决定自动升级成正文发送。

内联正文的记忆仅来自精确配对的原生工具调用和确认成功结果；未知、拒绝、错配、压缩重写和越过角色边界的记录不视为已发回复。传输接受仍不等于客户端实收。

群聊短缓冲从真实收件开始计时，队列中的等待计入原窗口。持续输入按同批首条时间封顶，最新输入仍是当前权限依据；已排队超过窗口的输入不再追加完整缓冲。正常空闲群的短缓冲、直接艾特窗口和私聊并行保留。减少一个模型步骤不等于承诺固定响应秒数，必要媒体、压缩和外部模型仍有真实耗时。

## 旁听与参与

配置群的普通未艾特消息在旁听时不领取实时输入、不启动模型、不预留模型预算，只为既有自主机会保留同范围同归属最近12条、每条最多1600字符的历史观察。真实艾特或核实的同群引用回复可直接打开参与；自主决定reply本身不打开，必须实际群消息发送成功。@all、引用其他人和文本伪造的寻址元数据均不打开。

配置群已有自主机会，且近两分钟没有新观察时，可向核验过的 QQ 后端读取同一群最近十二条历史。最近十分钟的有效成员文字与实时观察按时间合并，同一消息优先保留实时内容，合计最多十二条。查询期间收到新的实时观察时，沿用实时上下文。该读取沿用现有夜间休息、权限、会话归属和连接检查，由主模型判断是否接话。

同群最近十分钟的直接来图已由接收管线解析时，主 LLM 可在配置群的自主轮用 `qq_view_group_image` 查看一张图。群话题按真实到达顺序保留先到但较晚解析的图，实时队列仍按较新来信处理。提示只附不含文件路径的引用，工具通过本地缓存返回真实附件。图片缺失、换档、回合过期或实时输入抢占时，模型可依据现有文字判断。读图不改变群参与状态和发送权限。

已参与的话题沿用群聊短缓冲和最新说话人权限，无需每句重新艾特。主 LLM 可以用 `group_conversation=end` 结束话题。实时 `idle`、`defer` 和 `silence` 默认结束，实时 `continue` 只延续当前话题。十分钟内没有新的直接联系、确认发出的群回复或实时 `continue`，会回到旁听。自主检查选择安静不会延长这个窗口，接下来的普通消息仍可供自主机会参考。迟到旧轮次不能关闭新艾特。进程重启、停止或归属变更从旁听开始，原平台历史不删除。参与资格不授予额外发送或静默控制权限。

阶段诊断将group_listening单独记为旁听，不算漏答或长期积压；缓冲阶段仍保留真实queued/claimed状态，不冒充已回复。

## 实时回复中的可选表情

实时问候曾在四个无描述候选间逐张看图，之后仅发文字；实际等待主要发生在多轮模型／视觉步骤。当前领取为图库提供实时选择限制：同一回合一次挑选、最多一张候选，重复请求只提示复用或正常文字回退，不再查库或暂存。清楚的描述可用于普通反应，无描述图片仍要看真实内容，不合适时不继续图库巡游。该限制不改用户输入图片的读取，也不限制回答必要问题；自主回合与网页选择保持原语义。选图仍不是发送，表情仍需当前票与实际回执。

## 服务内漏答巡检

原生 QQ 服务启动后，每三十秒独立执行一次漏答检查，不依赖自主活动额度或 Codex 定时任务。已通过真实接收管线的私聊、直接艾特，以及核实为回复机器人的同群引用，可以异步登记有界原文、归属和时间。排队合并或已领取的回复被打断时，只要下一轮仍带有原联系正文，就保留补答资格，并沿用最新发言人的权限。普通群讨论、艾特全体、艾特别人、引用中的艾特和被过滤的消息不会触发补答。超过正文上限的输入继续由原生队列处理。

等待至少一分钟、会话空闲、连接正常、当前归属和权限一致，且当前真人输入未被更新输入替代时，才有机会补查。宿主重启后，原生队列若只剩一条能与当前来信证据核对的 QQ 输入和可识别的原生上下文，巡检先保留原始入队事件，再通过 SDK 领取一次补答机会。若模型已选择 idle／defer／silence，或该 revision 曾产生任何发送记录，包括部分发送、预留、失败后保留、未知及抑制，均不自动重试。界面显示“正在运行”或模型有文本草稿，都不能代替这些证据。

领取补查在原有策略事务中完成：撤销原票、固定同一输入的单次尝试，再由同一个会话的主 LLM 参考最新对话决定简短回答或安静。它不是伪造新来信；历史正文不再提供管理员角色、静默／恢复控制或工具动作权限。补答仍需新决定、新票、实际预算和出口检查，实际类别为私聊／群聊，不挤占自主额度，也不会被自主夜间休息拦住。原轮未知费用保留，不借补查清账。

同条输入至多一次补答入队尝试，持久化次数跨重启保留。会话创建或上下文准备失败且能确认队列尚未触碰时，可在下轮巡检重试准备。队列写入结果不明时保留该次领取。每轮最多检查六十四个候选、领取四个会话，轮转避免一个不可用范围挡住其他人。自主观察会让位于仍待检查的当前来信，已接受安静或补查后可继续自主活动。

下一轮领取时继承的未回答内容，也写入当前来信的补答证据。更新要求同一条待回答来信、同一归属和原补答文字，沿用原等待时间。

QQ 重连并完成映射与账号核验后，立即检查已恢复的好友私聊和配置群，也会查看最多二十四个符合权限但尚未建立会话的当前好友。每轮选取最多八个会话、并行读取三个。名单或历史查询临时失败，以及会话仍在处理来信时，会在三分钟窗口内留待后续巡检。每次最多取每个会话最近十二条历史，最多八条合入原会话的一次补答。好友私聊补查普通文字，配置群补查真实文字艾特，保留发言顺序与发言人区别。已接收、已有后续己方发言、会话更新、权限变化或后端切换会阻止补收。普通群聊、引用、临时私聊、媒体和命令走实时接收。旁听缓冲为空时，自主轮也可参考最近十分钟的同群历史文字。诊断分别记录 `friend_history_staged` 和 `group_history_staged`。

补查覆盖到当前连接首次完成账号核验的时刻。历史查询重试沿用这个时间上限。配置群即使还没有本地会话或策略记录，也会检查近期历史。第一条真实文字艾特可以由补答巡检建立会话，普通消息只补充旁听资料。

检查周期不等于回复时限。证据异步落盘前崩溃、媒体准备失败、超出重连窗口的消息及已领取后再次崩溃，仍可能需要人工核对。相关回归位于 `test_reply_review.mjs` 与 `test_onebot_live_inbox.mjs`。手机实收由客户端确认。

## 阶段诊断

启用原生 claim 的适配器在本机策略文件所在目录写入 `interaction-health.jsonl`，只保存时间、范围／输入哈希、阶段和限定状态。诊断写满八 MiB 时轮转，上一段可用 `--previous` 查看。原始消息和策略账本仍由各自服务保存。

从源码目录运行：

```powershell
python -B scripts/interaction_health.py --log ABSOLUTE_PRIVATE_INTERACTION_LOG
```

脚本只读有界普通文件，按会话哈希汇总阶段、长时间未结束条目和耗时。连接验证、入站准备和接收至传输接受各自提供样本量及分位数。用 `--since-ms` 加 Unix 毫秒时间戳，可查看部署后的输入。更早的记录仍参与关联跨窗口合并的会话。安静决定、未准入、准备失败、排队、已领取、拒发、传输接受和未知分别展示。手机端显示需由客户端确认。

如需核对短暂断线或重载期间的收件，用 `--friend-mapping ABSOLUTE_CHAT_SESSIONS_JSON --since-ms UNIX_MS`，时间窗口为最近 24 小时内。该模式对照选定 QQ 后端的好友私聊历史与两段阶段日志，最多检查 32 个已映射私聊，每个读取最近 50 条。缺接收记录标为 `without_ingress_evidence`，历史读不到或覆盖受限时报告 `partial`。结果只含汇总数字，供定位收件链路。

合并的入站依据有序阶段元数据关联为 `coalesced`，不会继续冒充积压；缺失父阶段时明确为部分来源。拒绝的静默控制不计作已接受安静，发出部分包后又拒发单列 `partial_transport`，不能冒充完整发送。这些关联仅用于诊断，不重建票或重放权限。

准备前就被权限／过滤拒绝的事件，可能只有 `not_admitted`；精确过滤原因仍需对照原生接收管线。`turn_end` 可能早于异步发送结束，不能立刻把它判为漏回复。没有样本时耗时保持 `null`，不用零冒充正常。

## 明确边界

本批没有清空会话、改模型、取消必要工具或放开安全闸门。普通回复仍需要模型生成与发送决定；合适的表情、视觉工具和语音会增加真实步骤。同步压缩和供应商请求仍可能等待，不能承诺固定秒数。

接收减压只用于已核验原生会话与允许的队列状态，保留接收拥挤边界；不同权限输入不强行合并成同一个有权请求。持续洪流不保证逐条回复，合并的历史有条数与长度边界。归属尚未确认或媒体仍在解析的较早输入，不假装已经完整进入更新上下文。

DSH 停止或连接不可用期间，未到达接收管线的消息不在本机阶段日志里。恢复后的补收受前述时间、消息类型及回执条件约束。故障验收应选取恢复后的新输入，分别核对入口、原生回合、决定、传输回执和真实客户端显示。
